# Формат пака

Короткая карта правил манифеста и архива. Рабочий пример со всеми
обязательными частями — [`packs/example/letter-triage/`](../packs/example/letter-triage/):
это минимальный, но полный пак, стоит открыть его рядом с этим документом.
Все правила ниже проверяет `python3 tools/pack.py check packs/<ns>/<name>`
локально и `python3 tools/pack.py validate packs/<ns>/<name>` — той же схемой,
что и подача.

## Манифест (`pack.yaml`)

- `apiVersion: aios.dev/v1alpha1` — версия ДОГОВОРА (схемы манифеста), не
  версия содержимого пака. Правка описания поля не требует от автора новой
  версии пака.
- `kind` — ровно один из трёх, смешивать нельзя:
  - **Pack** — направление данными: домены, агенты, workflow; коннекторы
    разрешены. Пуст и отклоняется, если нет ни одного из
    domains/agents/workflows/connectors.
  - **Connector** — только коннекторы; домены, агенты и workflow — отказ.
  - **Solution** — композиция уже опубликованного: только
    `spec.components.includes`, минимум 2 точные ссылки
    `namespace/name@version` без повторов. Своего содержимого,
    `requested_capabilities` и `secrets` у Solution не бывает — права и
    секреты принадлежат составным частям и выдаются им отдельными грантами.
- `metadata.namespace` и `metadata.name` — машинное имя
  `^[a-z][a-z0-9-]{1,62}[a-z0-9]$` (строчная латиница, цифры, дефис,
  3–64 знака). `namespace` закрепляется за издателем навсегда.
- `metadata.version` — строгий semver `д.д.д`, без пред-релизов.
- `metadata`: `publisher` (3–64 симв.), `title` (3–120), `summary`
  (20–500, идёт на витрину), `license` (2–64, лицензия САМОГО пака — не
  лицензия этого репозитория), `homepage` (необязательно, ≤300).
- `metadata.categories` — 1–3 значения из закрытого списка: `sourcing`,
  `documents`, `analytics`, `observability`, `integration`, `knowledge`,
  `automation`. Список закрыт: рубрика — про НАЗНАЧЕНИЕ пака, а не про
  отрасль; больше трёх читается как «подходит всем».
- `metadata.keywords` — до 10 машинных слов (тот же алфавит, что у имени),
  без повторов. Отрасль и всё остальное — сюда, свободными словами, но
  строчной латиницей.
- `spec.compatibility.min_aios` обязателен (semver); `max_aios` — semver или
  пусто (пусто значит «не знаю», а не «работает всегда»).
- `spec.components`: `domains` / `agents` / `workflows` — списки машинных
  имён, уникальны (до 20/50/50); `connectors` — до 20.
- **Коннектор**: `name` (машинное имя), `type` ∈ `mcp | http | webhook | otlp`,
  `endpoint` (обязателен, только `https://`, без `user:pass@`, без `?`/`#` в
  пути, домен обязан содержать точку — без голого IP), `endpoint_secret`
  (`^[A-Z][A-Z0-9_]{2,63}$`), `summary` (10–300). Адрес в манифесте — это
  заявление автора, а не право ходить: фактический адрес при вызове берётся
  из настроек установки, а не из этой строки.
- `spec.requested_capabilities` — просьба, не разрешение; только из закрытого
  набора:

  | право | что сможет | чего не сможет |
  |---|---|---|
  | `traces:aggregate` | видеть число вызовов, ошибки, задержки | узнать, кто пользовался |
  | `traces:sample_redacted` | видеть отдельные обращения без содержимого | прочитать данные внутри них |
  | `traces:raw` | ничего — площадка не выдаёт это право автоматически | получить сырые обращения даже с правом |
  | `network:egress` | обращаться к службам по списку адресов установки | ходить куда угодно ещё |
  | `source:query` | читать источники своего же направления | читать чужие дела и источники |
  | `learn:propose` | предлагать записи в отраслевой справочник | вносить их — вносит куратор |

  `traces:raw` и `traces:sample_redacted` вместе не просят — это разные
  согласия владельца данных. Права на отправку сообщений, платёж, заказ и
  подпись нет и не будет — такие действия имеют последствия за пределами
  площадки.
- Связность, которую проверяет схема: есть хоть один коннектор → обязателен
  `network:egress`, и наоборот; коннектор обязан ссылаться на имя из
  `secrets`, объявленное в этом же манифесте.
- `spec.secrets` — только ИМЕНА ожидаемых секретов (`^[A-Z][A-Z0-9_]{2,63}$`)
  и `purpose` человеческими словами (10–200 симв., «нужен для работы» не
  ответ). Значений секретов в манифесте не бывает — их приносит владелец
  установки.
- `spec.resources` — просьба «сколько нужно»: `timeout_seconds` (1–300, по
  умолчанию 15), `memory_mb` (16–2048, по умолчанию 128),
  `requests_per_minute` (1–6000, по умолчанию 60). При установке берётся
  минимум из просьбы и потолка яруса площадки.
- `spec.tests.fixtures` (по умолчанию `tests/`) и `spec.tests.evals` (по
  умолчанию `evals/`) — оба обязаны реально существовать в архиве; это
  проверяет сканер по факту содержимого, не схема манифеста.
- Все модели — `extra: forbid`: незнакомое поле — отказ. Отдельно: путей к
  python-модулям, строковых хуков исполнения, `custom_config`, списков
  разрешённых людей/ролей, готовых грантов и класса риска в манифесте не
  бывает никогда — это не то, чего «пока нет», а то, чего в договоре не
  появится.

## Файл направления (если объявлены `domains`)

Если `spec.components.domains` не пуст, для каждого имени нужен файл на
верхнем уровне архива: `<имя>.yaml`, `<имя>.yml`, `domains/<имя>.yaml` или
`domains/<имя>.yml`. В примере `letter-triage` — это `letter-triage.yaml`,
по имени из `components.domains`.

Содержимое проверяется той же схемой, что и штатные направления площадки —
второй, облегчённой схемы для чужих паков нет. Минимально обязательны:
`entity_types` (хотя бы один, типы уникальны) и `case_templates` (хотя бы
один); всё остальное — списки и поля с значениями по умолчанию, можно
оставить пустыми. Разбирать этот файл в деталях лучше по примеру
`packs/example/letter-triage/letter-triage.yaml` — там ровно необходимый
минимум, без лишних связей.

Кроме этого минимума схема направления знает и необязательные, но часто
нужные поля: `party_roles` (роли сторон дела друг для друга и их взаимная —
`reciprocal` — роль), `agents` (у каждого свои `min_assurance`,
`sensitivity_clearance`, `capabilities` из закрытого перечня) и
`platform_abilities` (список умений направления с `mode` —
`official_api`/`direct_fetch`/`own_corpus`/`isolated_browser`/
`user_browser`/`human_only`/`impossible`/`not_built` — чем направление
честно называет то, что уже работает, и то, чего нет). У `letter-triage`
их нет — это минимальный образец. Более полный образец, где эти поля
объявлены и заполнены осмысленно (включая шаги с денежными и личными
сведениями, для которых схема иногда требует подтверждённого входа —
подробность дальше в этом же абзаце) — [`packs/example/family-budget/`](../packs/example/family-budget/family-budget.yaml).
Отдельно: любой шаг плана, у которого `policy.allowed_ops` содержит
`add_draft_document`, схема обязывает быть `on_request: true` и
`min_assurance` не ниже 2 — это проверка, падающая при загрузке пакета, а
не соглашение авторов; для прочих операций (`add_panel` и т. п.) схема
такого порога не требует, даже если сам шаг несёт денежные или личные
сведения — тогда порог назначает автор пака сознательно, а не схема.

**Оговорка.** В отличие от `tests/`/`evals/`, само НАЛИЧИЕ файла направления
сканер площадки при подаче версии не проверяет — проверяется только то, что
объявлено имя в манифесте. Пак может пройти check → build → validate →
сканер → одобрение без файла направления и развалиться только при первой
установке у арендатора, когда исполнитель ищет этот файл по имени и не
находит. Локальный `tools/pack.py check` эту нехватку тоже пока не ловит —
дважды проверьте, что файл направления действительно лежит в архиве под
одним из перечисленных выше путей.

## Архив (`.tar.gz`)

- Только `tar.gz`, читаемый как обычный tar-архив со сжатием gzip.
- Пределы: архив сжатый ≤5 МБ; записей ≤500; один файл ≤2 МБ; суммарно
  развёрнутое содержимое ≤20 МБ (защита от архивной бомбы).
- Разрешённые расширения — закрытый список: `.yaml`, `.yml`, `.json`, `.md`,
  `.txt`, `.csv`. Кода (`.py`, `.js`, `.sh` и т. п.) не бывает никогда — пак
  декларативен.
- Пути записей проверяются до чтения содержимого: без абсолютных путей, без
  `..`, без ведущего `./` или `//`, без обратной косой черты, без
  управляющих символов в имени.
- Символические и жёсткие ссылки в архиве запрещены целиком.
- Обязателен файл `pack.yaml` буквально в КОРНЕ архива — установщик пака
  читает манифест только по этому точному имени и пути; вложенный
  `sub/pack.yaml` или файл с именем `pack.yml` сканер как манифест ещё
  засчитает, но при установке пак с таким именем будет отклонён с «в
  артефакте нет pack.yaml». Называйте манифест только `pack.yaml` и кладите
  его в корень архива, не полагаясь на более мягкую формулировку.
- Каждый годный файл обязан читаться как UTF-8.
- Секреты в тексте файла (закрытые ключи, токены известных провайдеров,
  буквальные `password:`/`token:` со значением) — отказ; само значение в
  отчёт не попадает.
- Попытки перехвата указания модели в тексте («забудь предыдущие
  указания», подделка служебной разметки, самовыдача прав и т. п.) — отказ:
  текст пака попадает в системную подсказку агента рядом с границами
  площадки, и это не стилистика, а адрес атаки.
- Вписанный в файл адрес `http(s)://`, кроме заведомо своих (`aios.dev`,
  `json-schema.org`, `example.com`, `localhost`), — не отказ, только
  замечание: коннектор всё равно берёт настоящий адрес из настроек
  установки, а не из текста файла.
- Архив принимается тогда и только тогда, когда среди находок сканера нет ни
  одной фатальной; замечание про вписанный адрес отчёт не портит.

## Метка выпуска

Для пути подачи по ссылке (`docs/podacha-ssylkoy.md`) архив публикуется как
файл выпуска GitHub под меткой `<namespace>.<name>@<version>` — печатает её
`python3 tools/pack.py tag packs/<ns>/<name>`, а собирает архив с этим именем
`python3 tools/pack.py build`. Подробности схемы — там же, в
`docs/podacha-ssylkoy.md`.
