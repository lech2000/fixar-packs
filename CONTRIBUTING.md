# Как добавить пак в этот репозиторий

Это один из двух путей подачи (второй — свой открытый репозиторий и ссылка,
см. [`docs/podacha-ssylkoy.md`](docs/podacha-ssylkoy.md)). Здесь описан путь
через PR в `fixar-packs`.

## Прежде чем открывать PR

Пространство имён (`metadata.namespace` в вашем `pack.yaml`) должно
принадлежать вам как издателю на площадке — то есть у вас уже должна быть
подана заявка издателя (`POST /registry/publishers`), закрепившая это
пространство имён за вашим субъектом. PR на пространство имён, которое вам
не принадлежит, не примут независимо от качества самого пака: слияние в этот
репозиторий не заменяет и не обходит проверку издателя на площадке — это
только место хранения и сборки архива.

Допуск публиковать (то есть решение площадки одобрять ваши версии) — отдельно
от занятия пространства имён и не проверяется на этапе PR: его проверит
площадка при подаче версии через API, уже после того, как ваш пак попадёт в
этот репозиторий.

## Что положить в PR

```
packs/<namespace>/<name>/
  pack.yaml
  <domain>.yaml        # если объявлены domains — см. docs/format.md
  tests/
  evals/
```

Один PR — один пак (или одна новая версия существующего пака). Перед
отправкой прогоните локально:

```bash
python3 tools/pack.py check packs/<namespace>/<name>
python3 tools/pack.py build packs/<namespace>/<name> --out dist
```

`check` должен завершиться без ошибок; `build` должен собрать архив без
предупреждений о недостающих `tests/`/`evals/` или запрещённых файлах.
Правила манифеста и архива — в [`docs/format.md`](docs/format.md); минимальный
рабочий образец — [`packs/example/letter-triage/`](packs/example/letter-triage/).

## Что проверяется

- **Автоматически, на каждый PR** (включая PR из форков): `tools/pack.py check`
  и `tools/pack.py build` для изменённых паков — расширения файлов, пределы
  размеров и числа файлов, отсутствие ссылок и симлинков, наличие `tests/` и
  `evals/`, совпадение namespace/name/version манифеста с путём в дереве.
  Дополнительно CI собирает пак ДВАЖДЫ и сверяет sha256 обеих сборок (проверка
  детерминированности) и вызывает живой `POST /registry/validate` на
  `api.agrigate.pro` — это сетевой вызов, срабатывающий автоматически на
  каждый такой PR.
- **Вручную, сопровождающими репозитория**: соответствие пространства имён
  заявке издателя на площадке, качество и ясность `summary`/`title`, отсутствие
  в тексте направления попыток перехвата указания модели (то же, что позже
  найдёт сканер площадки при подаче — лучше поймать здесь), уместность
  запрошенных `requested_capabilities` тому, что пак действительно делает.

Слияние в этот репозиторий не означает одобрение пака площадкой — это
раздельные решения. Слияние PR только помещает пак в дерево и позволяет
собрать и опубликовать для него архив.

## Кто ставит метку выпуска

Метку (`<namespace>.<name>@<version>`) и релиз в этом репозитории после
слияния ставят **только сопровождающие репозитория** — не автор PR. Это
намеренное разделение: слияние кода и выпуск архива, на который потом ссылается
подача версии, — два разных решения, и второе не должно происходить
автоматически по факту слияния без отдельного шага.

После того как релиз опубликован, пак ещё не подан на площадку: версию и
ссылку на архив (или байты) в API подаёт сам автор, от своего входа и
своего пространства имён — см. [`docs/podacha-api.md`](docs/podacha-api.md)
или [`docs/podacha-ssylkoy.md`](docs/podacha-ssylkoy.md). Этот репозиторий и
его релизы — только источник архива; решение о публикации на площадке
принимает не он.

## Язык и стиль

Тексты, которые читает пользователь площадки (`title`, `summary`, `note`), —
по-русски, на «вы», без эмодзи. Технические поля (`name`, `namespace`,
`keywords`, ключи полей) — латиницей по правилам формата, см.
[`docs/format.md`](docs/format.md).

`purpose` агента — особый случай: это не текст для пользователя, а указание,
обращённое к самому агенту (оно становится частью его системной подсказки), и
по конвенции площадки пишется на «ты» — как в примере
[`packs/example/letter-triage/letter-triage.yaml`](packs/example/letter-triage/letter-triage.yaml).
